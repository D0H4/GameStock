# 가격 차트 시뮬레이션

`bun run dev` 실행 후 `/simulation.html`을 연다. 기존 앱과 별도 진입점이므로 로그인, MarketProvider, 운영 API를 호출하지 않는다. 차트 하나에서 수정 전/후 전환, 일시정지, 재생 시점 이동을 지원한다. 상승은 초록, 하락은 빨강이며 기존 앱의 색상 규칙은 변경하지 않았다.

## 데이터와 재생

- `public/simulation/before.json`: 변경 전 커밋 `910c826`의 운영 엔진으로 생성한 고정 비교 기록.
- `public/simulation/after.json`: 현재 엔진으로 생성한 기록. `bun run simulate:chart`로 다시 생성하고 페이지를 새로고침한다. Java와 Maven이 필요하며 새 의존성은 없다.
- 공통 조건: UMA, 시드 `20261024`, 시작가 10,000원, 60분, 100ms 배치. 6,020명 모집단 중 원래 UMA에 배정되는 402명을 사용한다. 각 봇은 실제 자금과 보유 수량을 가진다. 나머지 종목은 실행하지 않으므로 전체 시장 부하 테스트는 아니다.
- `MarketSimulationHarness`의 `BotActivityEngine`과 `BatchOrderBook`에서 발생한 체결을 사용한다. DB, 인증 정보, 운영 계정에 접근하지 않는다. 정해진 가격 경로 또는 인위적인 캔들 모양을 입력하지 않는다.
- JSON 행은 `[경과 밀리초, 시가, 고가, 저가, 종가, 거래량]`의 1초 OHLC다. 각 초의 모든 체결에서 극값을 보존하며, 페이지가 이를 1분봉으로 집계한다. 1초가 완료되기 전에는 그 초의 체결을 노출하지 않는다. 거래 없는 분봉을 만들어 채우지 않는다.
- 화면은 완료된 실험을 30배속으로 재생한다. 브라우저에서 주문 엔진을 실시간 실행하는 페이지가 아니다. 창이 숨겨지면 재생 시간이 멈추며, 끝에서는 자동 반복하지 않는다.

## 변경과 검증 범위

호가 왕복으로 부풀려지는 변동성 추정, 양쪽에 무조건 바깥 틱을 더하던 LP 호가 반올림, 대형주 배분형 봇의 목표량 충족 후 왕복 주문을 수정했다. 대형주 단기 전략과 LP는 움직이는 합의가 및 최근 체결을 반영한다. 주문은 계속 기존 가격·시간 우선순위로 매칭하고 현금·수량·가격제한을 검사한다.

비교 기록의 첫 1분은 초기 호가 형성 구간이다. `bun run simulate:chart:stats`는 이후 완성된 분봉에서 `(고가-저가-|종가-시가|)/(고가-저가)`를 평균해 꼬리 비율을 계산한다. 보합 봉은 따로 세고 비율 계산에서 제외한다. 인자로 JSON 경로를 나열하면 다른 시드도 분석할 수 있다.

후속 수정의 시드 `20261024` 검증에서는 59개 분봉의 평균 꼬리 비율이 직전 구현 78.2%에서 65.6%로 줄었고, 몸통이 전체 길이의 절반 이상인 봉은 6개에서 22개로 늘었다. 추가 시드 7과 91의 새 구현은 각각 꼬리 비율 73.4%·67.6%, 해당 봉 13개·20개였다. 추가 시드의 직전 구현과의 비교를 수행한 것은 아니다. 횡보 구간의 긴 꼬리까지 없어진 것은 아니다. 페이지의 `수정 전`은 최초 커밋의 고정 기록으로, 직전 구현과 구분한다.

이 개선에는 대형주 봇 시간 압축 완화, 목표 수량을 넘기지 않는 소량 주문, 단기 전략의 합의가 반영, LP의 잦은 반대 거래 완화 및 합의가 확산 계수 조정이 포함된다. 이 페이지는 꼬리를 숨기거나 종가를 보간하지 않으므로 남아 있는 횡보·긴 꼬리도 그대로 보인다. 특정 시드의 차트를 실제 시장의 통계적 재현으로 해석하면 안 된다. 진단용 `-Dmarket.replay.trace=true`는 출력 JSON 옆에 체결 주체 및 합의가 기록을 별도로 저장한다.

회귀 테스트는 왕복 체결의 변동성 보정과 실제 점프 보존, 5초 VWAP, 목표 보유량에서의 주문 중단, 압력에 따른 호가 이동, 법정 틱·가격제한, 자금·주식 대사, 소형주 상·하한 근처 유동성, 뉴스 상승·하락과 자정 이후 거래를 확인한다. 상한 고착 테스트는 실제 하락 체결과 거래 지속을 요구하며, 하락 후 회복한 마지막 체결까지 반드시 시작가 아래에 있도록 강제하지 않는다.

차트는 최대 60개 봉만 Canvas에 그리고 데이터·크기 변경 때만 갱신한다. 브라우저 동작과 좁은 화면을 확인했지만 모든 장치·환경에서 120Hz를 보장하는 검증은 수행할 수 없다. 운영 DB 통합·부하 테스트와 배포는 이 작업에 포함되지 않는다.

## 2026-10-25 전 종목 후속 검증

### 17종목 운영 구성에서 발견한 전략 배정 쏠림

로컬 DB에는 기존 15종목 외 LT·MH가 있어 총 17종목이었다. `activePopulation`은 첫 20명 이후 전략을 17개 주기로 반복하고, `initializeActivityEngine`은 봇 순번을 종목 수로 나눈 나머지로 종목을 배정했다. 두 주기가 일치해 각 종목에 같은 전략이 약 350명씩 몰렸다. 기존 15종목 시뮬레이션 및 전략 다양성 검사는 이 조건을 재현하지 못했다.

2026-10-25 18:50~18:55 KST 읽기 전용 점검에서 스케줄러는 계속 주문을 냈지만, UMA·GI 등은 2주 체결이 약 60초 간격으로 반복되었다. 이는 `LiquidityRecoveryPolicy`의 60초 정체 감지와 2주 복구 주문에 부합한다. AK·TR은 LP 보유량이 0이고 대기 주문은 매수 쪽뿐이었다. 현금 고갈은 전체 봇의 공통 원인이 아니었다(6,020명 중 현금 1만원 미만 9명).

수정은 각 17개 전략 묶음을 별도 시드 난수로 섞어 순번 배정과의 고정 주기 결합을 없앤다. 계정 이름·종목 배정 방식·보유 자산·가격제한·체결·봉 집계는 바꾸지 않는다. 같은 시드에서는 같은 배정이 재현되며, 초기화 시 한 번만 섞는다. 15·16·17·18·34종목과 3개 시드에서 모든 종목에 모든 전략군이 배정되는 회귀 검사를 추가했다. 이 검사는 수정 전 17종목에서 실패했다.

악재/중립 비교 실험은 양쪽에 동일하게 참가자당 1주와 그에 상응하는 현금 차감을 초기 조건으로 넣었다. 공매도가 없는 시장에서 참가자 전원이 무주식 상태인 기존 조건은 전략 순서에 따른 최초 매수에 의존했다. 실제 하락 체결·중립 대비 낮은 평균 종가·자금 및 주식 대사 조건은 유지한다.

별도 발견: 현재 차트 API의 `volume`은 주식 수량이 아니라 체결/가격 기록 건수다. 따라서 이 필드가 5 이하라고 해서 5주 이하 거래로 해석하면 안 된다. 수량은 `bot_trade_minutes.quantity`로 따로 대조했다. 이 배정 수정은 해당 API 의미를 변경하지 않는다.

이번 수정은 전략 편중 결함을 해결하는 것이며 실제 주식 수익률 통계와의 동등성을 증명하지 않는다. 과거 봉을 다시 쓰거나 인위적인 가격 변동을 넣지 않는다.

### 종목 수 변경으로 방치된 기존 보유량

전략 분산만 적용한 뒤에도 ES·TR의 체결은 회복되지 않았다. 계정 순번 기반 현재 담당 종목과 실제 보유량을 대조하니 ES 508주·TR 512주 전부가 다른 종목으로 재배정된 봇에게 있었다. AK도 512주 중 15주만 현재 담당 봇에게 있었다. LP는 ES 4주·TR 0주로, 봇의 현금 부족이 아니라 매도 가능한 재고가 판단 대상에서 빠진 문제였다.

초기화 시 기본 담당 종목과 기존 보유 종목의 합집합을 각 봇의 관리 목록으로 만든다. 중복을 제거하고 계정별 관리 종목 수로 투자 예산을 분배한다. 판단 예정 시각과 보유 시작 시각은 계정 단독 키 대신 `(계정, 종목)` 키를 사용해 첫 종목의 판단이 다른 종목을 계속 막지 않도록 한다. 자산 강제 이동·보유량 초기화·직접 가격 변경은 없다. 주문 자금은 기존 매칭/저장 시점 계정 잠금과 최소 현금 검사로 검증한다.

회귀 검사는 15→17종목 전환 시 모든 기존 보유 종목이 관리 목록에 남는지, 중복·유효 종목·예산 분배·재현성을 확인한다. 동일 봇의 두 종목에서 실제 체결이 발생하는 테스트도 추가했다. 기본 `mvn -q verify`와 추가 다종목 테스트가 통과했다. 별도 MySQL 동시성 테스트 등 조건부 테스트는 기본 실행에서 제외된다.

### 19:12 BA 재현: 체결 불가능한 마지막 1주와 별도 ±6% 호가 제한

앞의 초기 20초 체결 확인은 정체 해결을 입증하지 못했다. 19:23:58 재조회에서도 BA는 15,630원이었다. 19:18~19:23 분봉 중 5개는 고가·저가 모두 15,630원이고, 나머지 한 개만 고가 15,640원이었다. 매도 15,640·15,650·15,660·15,670원에 각각 1주만 남아 있었다.

`BatchOrderBook.match`는 LP의 각 호가 마지막 1주를 사람 전용으로 남기며 봇 주문을 취소했다. LP 매수호가에도 같은 마지막 1주 및 별도 현금 잔여액 veto가 있었다. 가격·시간 우선순위상 맨 앞에 있는 공개 호가인데 봇은 소진할 수 없어 가격 탐색을 막았다. `quoteBand`는 대형주에 뉴스가 없으면 전일 대비 ±6%만 허용해, 봇 공통 ±20% 안에 있는 매도 의사도 걸러냈다.

수정은 이미 자금·재고를 예약한 공개 호가의 상대방별 거부 규칙을 제거하고, 호가 제한을 기존 봇 ±20%로 통일한다. 정체 복구 주문도 마지막 1주를 정상 체결 대상으로 본다. 일일 ±30%, 봇 ±20%, VI, 잔고 검증과 가격·시간 우선순위는 유지한다. 화면과 과거 봉은 변경하지 않는다.

회귀 검사는 스크린샷과 같은 BA 가격·네 개의 1주 매도호가를 실제 4주 매수로 모두 소진하고, 체결 가격 및 자산 보존을 확인한다. 기존 사람 전용 잔량 테스트는 공개 물량의 완전 체결로 변경했다. 유동성 테스트도 유한 자산과 실제 가격 경계를 구분한다. 48주를 모두 판매한 LP가 계속 매도호가를 남기거나, 봇 상한에 걸린 매수호가 위에 수동적인 매도호가를 내도록 요구하지 않는다. 사람의 왕복 주문도 실제 공개 매수 잔량까지만 체결되며, 미체결분의 보유량과 현금·주식 총량이 보존되는지 검사한다. 이 변경은 모든 시점의 양방향 유동성이나 즉시 매도를 보장하지 않는다.
