# 가격 차트 시뮬레이션

`bun run dev` 실행 후 `/simulation.html`을 연다. 기존 앱과 별도 진입점이므로 로그인, MarketProvider, 운영 API를 호출하지 않는다. 차트 하나에서 수정 전/후 전환, 일시정지, 재생 시점 이동을 지원한다. 상승은 초록, 하락은 빨강이며 기존 앱의 색상 규칙은 변경하지 않았다.

## 데이터와 재생

- `public/simulation/before.json`: 변경 전 커밋 `910c826`의 운영 엔진으로 생성한 고정 비교 기록.
- `public/simulation/after.json`: 현재 엔진으로 생성한 기록. `bun run simulate:chart`로 다시 생성하고 페이지를 새로고침한다. Java와 Maven이 필요하며 새 의존성은 없다.
- 공통 조건: UMA, 시드 `20261024`, 시작가 10,000원, 60분, 100ms 배치. 6,020명 모집단 중 원래 UMA에 배정되는 402명을 사용한다. 각 봇은 실제 자금과 보유 수량을 가진다. 나머지 종목은 실행하지 않으므로 전체 시장 부하 테스트는 아니다.
- `MarketSimulationHarness`의 `BotActivityEngine`과 `BatchOrderBook`에서 발생한 체결을 사용한다. DB, 인증 정보, 운영 계정에 접근하지 않는다. 정해진 가격 경로 또는 인위적인 캔들 모양을 입력하지 않는다.
- JSON 행은 `[경과 밀리초, 시가, 고가, 저가, 종가, 거래량]`의 1초 OHLC다. 각 초의 모든 체결에서 극값을 보존하며, 페이지가 이를 1분봉으로 집계한다. 1초가 완료되기 전에는 그 초의 체결을 노출하지 않는다. 거래 없는 분봉을 만들어 채우지 않는다.
- 화면은 완료된 실험을 30배속으로 재생한다. 브라우저에서 주문 엔진을 실시간 실행하는 페이지가 아니다. 창이 숨겨지면 재생 시간이 멈추며, 끝에서는 자동 반복하지 않는다.

## 변경과 검증 범위

호가 왕복으로 부풀려지는 변동성 추정, 양쪽에 무조건 바깥 틱을 더하던 LP 호가 반올림, 대형주 배분형 봇의 목표량 충족 후 왕복 주문을 수정했다. 대형주 단기 전략과 LP는 움직이는 합의가 및 최근 체결을 반영한다. 주문은 계속 기존 가격·시간 우선순위로 매칭하고 현금·수량·가격제한을 검사한다.

비교 기록의 첫 1분은 초기 호가 형성 구간이다. `bun run simulate:chart:stats`는 이후 완성된 분봉에서 `(고가-저가-|종가-시가|)/(고가-저가)`를 평균해 꼬리 비율을 계산한다. 보합 봉은 따로 세고 비율 계산에서 제외한다. 인자로 JSON 경로를 나열하면 다른 시드도 분석할 수 있다.

후속 수정의 시드 `20261024` 검증에서는 59개 분봉의 평균 꼬리 비율이 직전 구현 78.2%에서 65.6%로 줄었고, 몸통이 전체 길이의 절반 이상인 봉은 6개에서 22개로 늘었다. 추가 시드 7과 91의 새 구현은 각각 꼬리 비율 73.4%·67.6%, 해당 봉 13개·20개였다. 추가 시드의 직전 구현과의 비교를 수행한 것은 아니다. 횡보 구간의 긴 꼬리까지 없어진 것은 아니다. 페이지의 `수정 전`은 최초 커밋의 고정 기록으로, 직전 구현과 구분한다.

이 개선에는 대형주 봇 시간 압축 완화, 목표 수량을 넘기지 않는 소량 주문, 단기 전략의 합의가 반영, LP의 잦은 반대 거래 완화 및 합의가 확산 계수 조정이 포함된다. 이 페이지는 꼬리를 숨기거나 종가를 보간하지 않으므로 남아 있는 횡보·긴 꼬리도 그대로 보인다. 특정 시드의 차트를 실제 시장의 통계적 재현으로 해석하면 안 된다. 진단용 `-Dmarket.replay.trace=true`는 출력 JSON 옆에 체결 주체 및 합의가 기록을 별도로 저장한다.

회귀 테스트는 왕복 체결의 변동성 보정과 실제 점프 보존, 5초 VWAP, 목표 보유량에서의 주문 중단, 압력에 따른 호가 이동, 법정 틱·가격제한, 자금·주식 대사, 소형주 상·하한 근처 유동성, 뉴스 상승·하락과 자정 이후 거래를 확인한다. 상한 고착 테스트는 실제 하락 체결과 거래 지속을 요구하며, 하락 후 회복한 마지막 체결까지 반드시 시작가 아래에 있도록 강제하지 않는다.

차트는 최대 60개 봉만 Canvas에 그리고 데이터·크기 변경 때만 갱신한다. 브라우저 동작과 좁은 화면을 확인했지만 모든 장치·환경에서 120Hz를 보장하는 검증은 수행할 수 없다. 운영 DB 통합·부하 테스트와 배포는 이 작업에 포함되지 않는다.
