# 뉴스·거래 기반 가격 형성 모델

기준: 2026-10-22 백엔드 수정본. GameStock은 게임 뉴스와 주문으로 가상 시장을 만드는 시뮬레이션이다. 아래 수치는 실제 기업 가치나 수익률 예측이 아니다. 기준 구현은 `MarketService`, `MarketConsensusValue`, `PriceMetricService`, `DerivativeService`다.

## 1. 가격의 역할

| 값 | 계산·용도 |
| --- | --- |
| 실제 현재가 `stocks.current_price` | 마지막 실제 체결가. 매칭이 없는 동안 뉴스나 지표만으로 새로운 체결가를 만들지 않는다. |
| 일일 기준가 `stock_protection_state.day_reference` | 한국 거래일의 가격제한폭과 일간 등락 계산에 사용한다. |
| 평가가 `market_price_metrics.mark_price` | 최근 체결과 호가를 이용한 주식 자산 평가가. 실제 마지막 체결가와 다를 수 있다. |
| 뉴스 펀더멘털 `hidden_fundamental` | 고정 앵커와 최근 뉴스로 계산한 봇의 가치 판단 입력. 체결가에 직접 덮어쓰지 않는다. |
| 봇 합의가 `market_consensus_state.value` | 뉴스 목표로 천천히 이동하고 확률적으로 변하는 봇 판단값. DB에 상태와 난수 상태를 함께 보존한다. |
| 파생 기준 지수·ETF NAV | 종목별 고정 기준가격에 대한 현재 주가 비율로 계산한다. 일일 기준가와 분리한다. |

한 체결에는 매수자와 매도자가 동시에 있다. 이용자 순매수와 봇 순매도가 서로 대응한다는 사실만으로 상승·하락의 원인을 단정할 수 없다. `price-drivers`는 뉴스 지표, 거래량, 미체결 호가를 설명하며 인과관계의 증명이나 새 가격 산식은 아니다.

## 2. 뉴스는 고정된 관측 구간의 투영값이다

종목별 게시 시각(없으면 생성 시각)이 관측 시각 이하, 최근 24시간 이내인 뉴스 후보 최대 100건에서 관련성 필터를 통과한 최신 10건을 사용한다. 미래 게시 뉴스는 제외한다. 반응 지연이 있는 봇은 관측 시각을 해당 지연만큼 앞당긴다.

```text
I_i = clamp(뉴스 영향도, -10, +10)
r_i = clamp(1 - (관측 시각 - 게시 시각) / 24시간, 0, 1)
n_i = sign(I_i) × L_i × abs(I_i) / 10 × r_i
```

| 뉴스 조건 | 건별 최대 영향 L_i |
| --- | ---: |
| 일반 | 2% |
| abs(I_i) >= 6 | 5% |
| I_i <= -8이고 사건·사고 문맥 확인 | 10% |

`N24 = clamp(sum(n_i), -한도, +한도)`이며 일반 집계 한도는 5%, 특별 뉴스가 포함되면 10%다. 종목 크기를 반영한 펀더멘털은 다음과 같다.

```text
bias = N24 × StockMarketProfile.movementWeight
multiplier = 1 + clamp(bias, -0.5, 소형 투기 종목이면 3, 그 외 1)
hidden_fundamental = anchor_price × multiplier
```

현재 상한 N24와 종목 가중치 때문에 실제 도달 가능한 범위는 위 최종 방어 상한보다 좁다. 동일한 뉴스 집합·관측 시각·앵커는 수집 배치를 나누어도 같은 값을 만든다. 기존 기사 수정, 24시간 경과도 다시 계산한다. 과거 구현처럼 이전 펀더멘털에 수집 배치 합계를 반복 곱하지 않는다. `news_price_state`와 옛 뉴스 커서는 호환용으로 남지만 현재 뉴스 투영값의 근거가 아니다.

봇의 뉴스 관측 캐시는 최대 30초이며 `NewsChangedEvent`로 무효화한다. 관리 작업이 펀더멘털을 재계산하고 주문 배치가 이를 관측하므로 기사 저장과 모든 봇 반응이 동일한 순간에 일어나는 것은 아니다. JDBC와 MySQL 세션은 모두 UTC를 사용한다.

## 3. 종목 크기와 봇의 가격 판단

`StockMarketProfile`의 활성 이용자 수는 외부 실시간 통계가 아닌 종목별 시뮬레이션 입력이다. 원신 1,500만, 우마무스메 300만, 트릭컬 5만 등 종목별로 다르다.

```text
virtualMarketCap = activeUsers × 100,000
size = sqrt(activeUsers / 450,000)
movementWeight = 대형이면 max(0.10, 0.45 / size), 그 외 min(2.5, 1 / size)
liquidityWeight = 대형이면 min(10, 2 × size), 그 외 max(0.35, 0.65 × size)
```

대형 종목은 WH, ZZZ, GOV, GI, BA, UMA, SR, OW다. 종목별 정확한 입력은 `StockMarketProfile`을 기준으로 한다.

봇 합의가는 `MarketConsensusValue.observe`가 갱신한다. 대형 뉴스 목표는 일일 기준가 주변에 제한하고, 소형은 펀더멘털과의 로그 가격차를 일부씩 반영한다. 목표로 향하는 반감기는 대형 60분, 소형 30분이다. 확률 변동은 경과시간의 제곱근에, 시장 국면의 방향성은 경과시간에 비례한다. 한 관측의 시간 간격은 최대 60초로 제한하며 긴 중단 동안의 가상 체결을 만들지 않는다. 합의가는 봇 일일 가격대 내부에 제한된다.

종목별 합의가·관측 시각·SplitMix64 난수 상태는 체결을 저장하는 트랜잭션에서 함께 저장한다. 새 배치 판단은 커밋된 상태를 읽고, 같은 주문 배치의 DB 재시도는 이미 정한 계획을 사용한다. 따라서 재시작이나 소유권 이전 시 합의가가 뉴스 목표로 갑자기 재설정되지 않는다. 이는 전체 봇 스케줄·모든 외부 입력까지 완전히 재현한다는 의미는 아니다.

## 4. 주문, 체결, 평가가

시장가는 반대편 최우선 호가를, 지정가는 가격·시간 우선순위에 맞는 호가를 소비한다. 남은 시장가 수량은 취소한다. 매칭 엔진은 실제 체결가를 기록하고 마지막 체결을 현재가로 반영한다. VWAP는 실제 거래대금을 수량으로 나눈 지표다. 과거 문서에 있던 “뉴스의 40%를 현재가에 직접 반영하고 봇 VWAP를 틱당 ±0.5%/±1%로 덮어쓴다”는 절차는 현재 경로가 아니다.

이용자 체결 수수료는 매수·매도 각각 0.1%이고 내부 봇 계정에는 별도 면제 정책이 적용된다. 현금, 보유 수량, 체결, 정산, 시장 revision은 같은 트랜잭션에서 변경한다. 봇 전용 상세 거래는 압축 원장과 초·분·시간 집계로 보존하며 이용자 거래는 관계형 원장에 남는다.

밀리초 타임스탬프와 종목 revision 기반 `execution_sequence`를 함께 사용한다. 같은 밀리초의 이용자·봇 체결도 저장 순서로 비교한다. 봇 버킷은 버킷 시작 시각 대신 실제 마지막 체결 시각과 순서를 사용한다. 기존 초 단위 기록에서 이미 사라진 과거 밀리초 순서를 복원할 수는 없다.

평가가는 최근 60초의 체결 VWAP, 호가 중간값, 마지막 체결로 계산한다.

```text
mark = 0.7 × VWAP
     + 0.2 × clamp(mid, VWAP × 0.99, VWAP × 1.01)
     + 0.1 × clamp(last, VWAP × 0.99, VWAP × 1.01)
```

체결이 없는 관측 구간은 마지막 체결값을 사용한다. 평가 갱신은 250ms 이내 중복을 합칠 수 있지만 실제 체결 원장과 현재가 저장은 동기적으로 처리한다. 이 방어식만으로 모든 시세조종 가능성이 제거됐다고 보지는 않는다.

모든 종목의 이용자 일일 가격제한폭은 기준가 대비 ±30%, 봇 체결 제한은 ±20%다. 대형 종목의 봇 호가에는 뉴스에 따라 넓어지는 추가 범위가 있다. 시장가 보호 범위, 호가 단위, VI도 함께 적용되므로 단순한 비율만으로 체결을 보장하지 않는다.

## 5. 실행 주기와 LP 재고

기본 설정은 참여자 6,020명, 최대 4개 매칭 그룹, 활성 배치 간격 250ms다. 종목별 목표 체결 속도는 부하·유동성·보호장치에 영향을 받는 목표값이며 보장값이 아니다. 적응형 모드에서 2분간 이용자 활동이 없으면 30분 주기 짧은 매칭으로 전환하고, 지나간 시간의 체결을 소급 생성하지 않는다.

LP 비상 재고 공급은 무제한이 아니다. 기존 재고가 4주 이하이고 근처 다른 매도 물량도 부족할 때, 종목 전체 유통량 상한 안에서 최대 32주를 보충한다. 초기 공급과 추가 공급량은 `market_inventory_issuance`에 기록한다. 사람의 수동적 보유량도 유통량에 포함한다.

대사는 “주식 수량이 항상 고정”이 아니라 “기존 수량 + 명시적으로 발행한 수량 = 이후 수량”으로 검사한다. 기존 DB에 과거 발행 기록을 추정해 만들지 않으므로 마이그레이션 이후 구간의 발행량 차이를 비교한다. 현금은 수수료를 합쳐 대사한다.

## 6. 파생 가격·만기·공통 자산 평가

`derivative_index_bases`에 종목별 기준가격을 한 번 저장한다. 최초 업그레이드 때는 기존 일일 기준을 사용해 당시 호가를 이어받고, 이후 자정의 일일 기준 변경은 지수와 ETF NAV를 재설정하지 않는다. 종목 구성 자체를 바꾸는 작업에는 별도 기준 조정 검토가 필요하다.

옵션 지수는 약 3초 주기 평가 갱신과 옵션 진입 때 `derivative_index_observations`에 기록한다. 만기 기준은 **만기 시각 이하의 마지막 영속 관측값**이다. 정확히 만기 순간의 모든 거래를 재구성하는 방식은 아니다. 한 번 결정한 `derivative_expiry_fixings`는 수동 청산·스케줄러·지연 복구가 공유한다. 만기 처리에는 청산 수수료를 부과하지 않는다.

만기 이전 기록이 없으면 정산을 보류한다. 업그레이드 전에 이미 만기된 포지션을 현재 지수로 임의 정산하지 않는다. 관측은 기본 30일 보관하되 미정산 만기에 필요한 이전 관측을 남긴다. 고정 만기값은 90일 이후 미결 포지션이 없는 항목부터 정리한다. 평가는 ID 커서와 시작 시점 최대 ID로 모든 OPEN 포지션을 500개씩 순회하므로 앞의 ETF 5,000개가 뒤 만기를 막지 않는다.

`AccountValuation`이 담보·랭킹·시즌에 공통으로 제공하는 총자산은 현금 + 예약 현금 + 미정산 순매도대금 + 주식 평가액 + OPEN 파생 평가액이다. 순자산은 대출을 뺀 값이다. 선물·매수 옵션은 손실 제한 계약이므로 파생 평가액의 하한은 0이다. 파생 평가액은 마지막 저장 평가 기준이며 매 요청의 실시간 호가와 미세한 시차가 있을 수 있다. 주간 성과는 여기에 보상·외부 현금 조정을 별도 반영한다.

담보 반대매매는 주문 제출액 대신 실제 잔액을 다시 읽고 다음 보유 자산을 처리한다. 주식으로 충분하지 않으면 파생자산도 동일한 정산 경로로 청산한다. 시즌 초기화는 과거 파생 포지션을 RESET으로 종료하고 재현금화를 막는다. 파생 `cash_flow`는 전 상품에서 수수료를 포함한 실제 현금 증감액이다.

## 7. 검증과 운영 적용

DB 테스트는 운영 데이터와 분리한 임시 MySQL 스키마에서 실행한다. `market.test.jdbc`, `loan.test.jdbc`, `ADMIN_TEST_JDBC`에 로컬 테스트 URL을 명시하고 JDBC 옵션 `connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true`를 사용한다. CI도 이 DB 테스트와 활성 부하 테스트를 실행한다. 고정 초기 시드가 필요하면 프로세스 환경변수 `GAMESTOCK_SIMULATION_SEED`를 지정한다. 미지정 기본값은 실행별 무작위 시드다.

재현 기록에는 코드 버전, DB 상태, 관측 시각, 가격 기준, 주문·보유·현금, 뉴스 게시 시각, 합의가 체크포인트와 난수 상태가 필요하다. 초기 시드 하나만 같다고 전체 시장 재생이 같아지지는 않는다.

배포 시 스키마 마이그레이션 잠금 아래 새 테이블·순서 컬럼·타임스탬프 정밀도·자원 제한 테이블을 추가한다. 기존 ETF OPEN 원장은 `cash_flow_version=1`인 행만 수수료를 한 번 보정하고 버전 2로 전환한다. 구버전 인스턴스가 동시에 쓰지 않는 통제된 배포가 필요하다. 큰 테이블 ALTER와 원장 갱신 시간은 운영 데이터 규모로 따로 확인해야 한다.

게시글·태그·알림 쓰기는 계정별 기능당 분당 10회다. 태그는 계정·종목별 100개, 댓글은 계정별 1,000개, 알림은 활성 50개·누적 200개다. 뉴스 응답은 수신 중 3MB에서 중단하고 동시 원문 조회는 4개로 제한한다. IPv4·IPv6 사설·특수 목적 주소를 거부하지만 DNS 재바인딩 전체를 검증한 것은 아니다.

WebSocket은 경로별 최대 2,048연결, 구독 경로 입력은 초당 20개·인증 분당 6개·메시지 8KB로 제한한다. OpenAPI의 전달 IP는 `gamestock.http.trusted-proxy-addresses`에 명시한 프록시에서 온 경우만 신뢰한다(기본 loopback). 운영 프록시 주소는 실제 배치에 맞게 설정한다. 처리되지 않은 500 오류는 내부 예외 메시지를 응답에 포함하지 않는다.

이번 작업은 로컬 수정과 검증이다. 운영 배포·운영 데이터 정산은 수행하지 않았다. 이미 만기됐으나 과거 지수 기록이 없는 계약은 원장과 남은 가격 이력을 별도로 검토해야 한다.
